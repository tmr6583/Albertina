Fluxo de dados da extração Olist para o Supabase

Documento visual amplo da extração Olist no projeto Albertina. Ele mostra a trilha operacional entre UI, API, controle incremental, camada RAW, destino relacional modelado em CORE e consumo analítico em MART. A leitura deixa explícito onde cada dataset do ERP está hoje e para onde ele foi desenhado no schema do Supabase.

Como interpretar sem risco de ambiguidade

A persistência atual desta aplicação já grava controle operacional e payload bruto. As tabelas olist_core e views olist_mart representam o destino modelado confirmado nas migrations e guias técnicos. Sempre que um path ou payload ainda não estiver fechado, o item permanece marcado como [A CONFIRMAR].

Fluxo operacional

O que acontece entre o clique em Iniciar extração e a leitura final no Supabase.

01 · Disparo

UI e API

O menu /extracao aciona POST /api/extraction/run, faz polling de /api/extraction/overview, permite parada segura em /api/extraction/stop e baixa o log completo pelo histórico com /api/extraction/executions/{execution_id}.

02 · Controle

Execução

O backend registra andamento, logs e checkpoint incremental em olist_admin.sync_runs, sync_run_logs e sync_watermarks.

03 · RAW

Payload integral

Cada resposta confirmada da API pública entra em olist_raw.api_payloads com payload JSON completo, ids externos e timestamp de origem.

04 · CORE

Modelo relacional

As migrations já definem o destino em olist_core para cadastros, vendas, logística, fiscal, financeiro, CRM e operações.

05 · MART

Analytics

Views e materialized views em olist_mart consolidam fatos e dimensões para análise e consumo futuro.
